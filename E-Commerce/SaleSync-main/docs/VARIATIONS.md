SaleSync variations (schema 5)

variation_groups stores seller-defined dimensions for a parent products.id. product_variants links each variant_id to one parent product_id and immutable selected options. Each variant_id is a real products.id with one product_meta SKU and one inventory balance, not a second copy of inventory. Child stock items are excluded from catalog listings. Public responses omit inactive combinations; authorized editors retain them. Non-variation products and all historical identifiers remain valid.

Cart/order/reservation/return/refund line id is the purchasable stock-item ID. Variant order snapshots additionally retain productId, variantId, selected options, SKU, price and image. Different combinations are separate lines. Existing ledgers and foreign keys apply directly to that stock item. Discounts, payment settlement, cancellation and restocking keep their existing transactions and idempotency rules.

GET/PUT /api/v1/{seller|admin}/catalog/:parentId/variations uses existing sessions, CSRF and ownership/Management checks. Save requires parent revision plus the current revision of every existing variant. At most two groups and 100 combinations are supported. Existing combination identities are immutable; deactivate instead of deleting, and extend group values rather than removing historical definitions. Names or dimensions requiring incompatible identities need a new listing. Variant SKUs share the existing globally unique SKU namespace, ready for future authenticated mapping; no POS calls exist.

First allocation transfers all unassigned parent stock into explicitly entered variant balances and refuses active parent reservations. Later balance changes are audited stock adjustments. Historical base-product refunds restore unassigned parent stock, which cannot be purchased through the parent once variations exist. Explicit Allocate unassigned stock transfers those units to chosen variants without duplicating inventory. Buy Now preserves the existing cart and uses an account-scoped session draft across checkout refresh; changing accounts clears it.

Save a product before opening Manage variations. Enter group names/values, build combinations, fill actual SKU/price/stock and optional image URLs, and save with a reason. Existing authorized media upload URLs are supported. Category/subcategory fields use approved categories and existing subcategory metadata.

Before starting an older installation on this release, use node scripts/backup-database.cjs SOURCE.sqlite NEW-SNAPSHOT.sqlite (create the destination directory first). A verified WAL-safe snapshot of the supplied demo was saved at checkpoints/before-phase22-demo.sqlite before migration. Schema 5 adds only two relationship tables and an index; existing rows are preserved. Restore snapshots into a separate directory with the app stopped. Payments/refunds remain local test operations; PayMongo and POS synchronization are not implemented.
